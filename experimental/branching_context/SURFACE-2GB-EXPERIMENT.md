# Surface Book 2 2 GB GPU: partial-offload experiment

This experimental branch changes the dense Llama adapter and its fresh oracle from 99 to eight GPU layers. It is **specific to this branch**, affects the shared Qwen bridge as well as dense Llama, and is not a fleet-wide default. It is a minimal proof of possible partial offload, not a configurable release or full correctness qualification.

The Surface Book 2 13-inch test machine had 8 GB system RAM and a GTX 1050 Mobile with 2 GB VRAM. The source base is `49560783d2e535c5a3f1c303747cbb7c4bc99da4` and the native llama.cpp pin is `972d2313bc0bf0a45f634f77d95c9fb03aeab12c`. A separate build used CUDA 12.9, `CMAKE_CUDA_ARCHITECTURES=61`, `GGML_CUDA_FA=OFF` and the normal build tools. The model was `MiniCPM5-2B-SSS-Muon-Full-U068-Q5_K_M.gguf`. Model weights are a separate download.

A 256-token-context fresh-oracle probe tokenized “Hello world” and returned a logits vector using approximately 485 MiB of GPU memory. A 32K PCC server loaded eight of 43 layers and processed a longer BranchWrite prompt with approximately 745 MiB reported in use, but the file-creation task was stopped before completion. The full standard native probe has a separate 24 GiB free-memory admission guard, so it was **not** run on this 2 GB GPU; do not remove that guard and claim its qualification. GPU/CPU numerical parity, checkpoint restoration, long tasks, concurrent workloads, idle power-down and end-to-end file work remain unproven.

To reproduce safely, follow `experimental/branching_context/MINICPM-NATIVE.md`, use fresh owned build/output directories, build the exact pinned llama.cpp revision, explicitly configure the Surface's CUDA architecture and disabled flash attention, then build `llama` and run `build_llama_dense.py` against that owned build. Prepare a CPU profile separately before attempting CUDA. Use a short bounded test, monitor RAM and VRAM, and compare against an independent CPU oracle with predetermined tolerances. The existing script's 24 GiB guard remains in force for its full probe. A successful model load or normal llama.cpp run is not proof of COW correctness. This branch does not install or change drivers, power policy or any ISO.
