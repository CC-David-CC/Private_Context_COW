## Contract and cache identity

Keep the [mathematical contract](../spec/branching-context-api.md) authoritative: exact model inputs may include artifact references, and complete continuation state includes positions as well as KV/recurrent state. The existing text-only implementation is narrower than that contract.

Use three related records, with only one canonical history:

1. A retained input artifact contains the original image bytes, normalized encoder input identity, and the expected accepted embedding digest and grid metadata. The embedding payload itself is derived and evictable. The canonical input span references immutable identities, not a mutable path or URL.
2. A reusable encoder artifact maps normalized input plus the pinned encoder/preprocessing profile to those validated embedding bytes. The cache is an index over artifacts, not another conversation history.
3. An optional COW checkpoint contains the already-consumed model state and frontier, bound to the complete ordered input identity, position convention and execution receipts. Existing branch references select snapshots as before.

Permit deletion of every embedding payload while retaining original image bytes, encoder/preprocessing profile, expected embedding SHA-256, dimensions and grid. Re-running an encoder is numerical work: test repeat exactness across fresh processes and verify regenerated normalization and embedding identities before replay. A mismatch must return an explicit reconstruction error and leave historical identity and branch references unchanged. Do not silently pin embeddings permanently or widen the exactness contract if a profile cannot regenerate them.

Account for retained originals separately from evictable embedding payloads and model checkpoints, within explicit storage limits. Embeddings share the configured RAM/disk budgets, LRU and idle expiry; use 30 minutes during this campaign. A history reference does not pin the embedding payload. Active leases do protect payloads during use. Canonical originals follow reachability and retention policy. If a new retained input cannot fit, return a capacity error before acknowledging a save.

Restore a compatible model checkpoint without requiring embedding files or launching the encoder: position reconstruction uses retained metadata. Without a checkpoint, explicitly replay using cached embeddings, or re-encode and verify them first if absent. Strict checkpoint restore never silently becomes replay. Record actual encoder and model recomputation separately.

| Reuse key | Required identity |
|---|---|
| Image encoding | Full normalized-input digest; preprocessing implementation and settings; encoder/projector files; relevant tokenizer/model metadata; mtmd/native build; dtype, layout, execution device/profile and image-token limits. Record original-upload identity separately. |
| Encoded payload | Full byte digest, byte length, dtype/endian convention, row count, embedding width and grid coordinates. Verify finite values and all size arithmetic before native access. |
| Model prefix | Exact ordered text IDs and image input spans, embedding digests, placement, positions/visibility, text-model contract, and the supported native schedule/profile. |

Different work IDs may use the same authorized immutable artifact and model prefix. Operation IDs still identify work/retries, not cache contents. Enforce existing namespace/principal access before revealing or using an artifact. Q4 and Q8 never share a numerical model checkpoint. Sharing an encoder artifact across them requires separately verified encoder/input compatibility; defer that optimization initially.

Changing image bytes, crop/orientation, token limits, projector, preprocessing or grid must invalidate the affected reuse. A different picture with the same number of image-pad tokens must not alias the old prefix. A changed earlier image requires recomputation from the earliest changed model input onward; no rotary transformation is proposed to preserve its later computed suffix.
