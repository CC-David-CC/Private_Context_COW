# Presentation-bound coordinator request handoff

The optional `presentation` request is detached and validated before intent creation, namespace admission, or worker dispatch. It binds schema, namespace, kind, displayed message text and IDs, renderer fingerprint, and stable assistant output ID into the operation signature. Schema-1 intent serialization and publication calls remain unchanged when the option is absent.

At publication, the coordinator constructs the presentation spans from the actual canonical source lineage, consumed input IDs, resulting snapshot/controller, and request metadata. Namespace-bound create writes a deterministic internal root-fork annotation and then publishes its numerical root snapshot with the caller operation. Retries validate the original signed intent and Store receipt; presentation data is not reconstructed from mutable branch head state. Resume verifies the supplied assistant ID against the active presentation before dispatch. Input validation rejects malformed kinds, duplicate message IDs, output/input message ID reuse, noncanonical values, and schema bool-as-int corruption.
