## Test design

`seeded_cow_test` fills real `BranchPages` memory on the GPU using the seeded fixture generator. Its complete expected byte stream is generated separately by the C++ `fixture_cpu` oracle and loaded from a file; CPU expected bytes are not generated by reusing the GPU fixture header. It exercises reserve/grow/freeze/restore, verifies canonical and sibling contents, writes across a physical VMM page boundary, checks the two copied pages and byte counts, checks snapshot lifetimes and cleanup, and hashes actual page contents. Critical allocation/map/restore failures terminate the case rather than continuing with invalid pointers.

With two CUDA devices, `stage_branchpages_group_2card` creates actual `BranchPages` pools on devices 0 and 1, performs `cudaMemcpyPeerAsync`, and compares the generated/transformed stage data against independent CPU arithmetic. With three devices, `stage_branchpages_group_3card_mixed` additionally uses device 2 and explicitly sends stage 1 to stage 2 through pinned host staging; the fallback records the full byte extent and never calls peer-copy for that edge. Both cases capture one native snapshot per stage. Group restore validates the exact stage count, device, and page metadata and probes snapshot contents in temporary `BranchPages` mappings before changing any active mapping; a missing-stage group must fail while every active pool remains untouched. Each device has a separate canary. These are model-free primitives, not a production model-state serializer.

`fixture_pressure` generates every chunk afresh on the GPU and compares it with the independent `fixture_cpu` process. It can additionally allocate a requested resident device extent, populate it from GPU-generated chunks, and read every resident byte back for exact verification. If the requested full resident extent is unavailable or exceeds the logical span, it reports staging-only status and the actual resident bytes separately. Disk output uses a bounded rotating dense window plus a bounded independent-oracle window: each is fsynced, reread, byte-compared, and SHA-256 checked before reuse. Host residency is bounded to two chunks and staging-device residency to one chunk; resident-device bytes are reported separately. The JSON result includes GPU generation, chunk transfer, resident readback, dense write, fsync, and disk readback microseconds. No full Q4/Q8 span was run.
